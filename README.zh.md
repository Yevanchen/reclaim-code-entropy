# 回收代码熵

> 一个以证据为先、用于安全化简任意代码库的 Agent Skill。

[English](./README.md) | 简体中文

## 问题所在

代码库积累的不只是静态意义上的死代码，还包括重复事实、废弃的扩展点、已经没有消费者的兼容路径、描述同一生命周期转换的多个状态，以及只会搬运复杂度的包装层。

静态工具可以生成候选项，但无法证明字符串分发的路由、公开导出、迁移、持久化格式、插件入口或异步清理路径真的可以安全删除。

## 解决方案

`reclaim-code-entropy` 用证据驱动化简：

| 阶段 | 要回答的问题 |
| --- | --- |
| **建立契约边界** | 哪些内容是公开、持久化、生成、动态加载或兼容敏感的？ |
| **扫描代码熵** | 多余的表示、状态、API、层和策略在哪里？ |
| **证明可以删** | 谁在消费它、为什么当初要加、删除会失去什么能力？ |
| **一次化简一个边界** | 能否端到端移除旧契约，而不是补一层新的胶水？ |
| **验证行为** | 如果删错了，哪一个最小检查一定会失败？ |

这个 Skill 宁可给出少量经过证明的删减，也不输出一长串猜测性的清理清单。没有发现安全可删项也是有效结论。

## 它会寻找什么

- 没有消费者的 API、导出、配置、事件和包
- 同一事实的镜像状态与重复表示
- 推测性抽象、永远固定的开关和废弃 fallback
- 只做转发的包装层，以及通往同一行为的多条路径
- 重复表达 ready、cancel、settle、dispose 的生命周期状态
- 对同进程、强类型交接进行的无效防御
- 标准库、平台或现有依赖已经覆盖的自建基础设施
- 实现已删除、但测试或文档仍然残留的内容
- 为某个想法加入、后来却没有完整撤回的代码

## 两种模式

**审计模式**按置信度、风险、取舍和预计净删减量排列候选项，不修改仓库。

**执行模式**实现证据最充分的安全删减，保留可观察行为，并运行与风险相称的验证。

## 安装

### 方式 A：Codex Skill Installer（推荐）

对 Codex 说：

```text
Install the reclaim-code-entropy skill from https://github.com/Yevanchen/reclaim-code-entropy/tree/main/skills/reclaim-code-entropy
```

安装后新建一个 Codex 任务即可使用。

### 方式 B：手动安装

```bash
git clone https://github.com/Yevanchen/reclaim-code-entropy.git
mkdir -p ~/.codex/skills
cp -R reclaim-code-entropy/skills/reclaim-code-entropy ~/.codex/skills/
```

## 使用方式

只审计，不修改仓库：

```text
使用 $reclaim-code-entropy 审计这个仓库，并按安全程度排列最值得做的化简。
```

实施最可靠的一次删减：

```text
使用 $reclaim-code-entropy 化简这个仓库。保留公开和持久化行为，只实施一个高置信度删减并完成验证。
```

调查特定区域：

```text
使用 $reclaim-code-entropy 检查这些生命周期 flag 是不同状态，还是重复的所有权表达。
```

## 核心洞察

删除量不是目标。真正的目标是减少团队必须持续保持一致的事实、契约、状态和概念数量。

大规模删除也可能是错的；很小的删除却可能消除一整项维护义务。决定性证据来自消费者关系、所有权模型、历史、兼容面和验证边界。

## 如何判断它在起作用

有效结果应当可审查、减少概念且不掩盖兼容风险；证据不足时，“保留不动”仍是正确结论。

## 安全边界

这个 Skill 不会删掉授权、信任边界验证、无障碍基础、数据丢失防护、持久化兼容，以及确保资源真正停止所必需的清理逻辑。

除非目标明确是通过化简改善性能，否则它不是性能审计工具。

## 灵感来源

最初的想法来自对 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness/commits/master/) 及其 Agent 驱动开发中代码化简实践的观察。本项目把这套思路推广到任意语言和技术栈的仓库；它是独立项目，与 DeepSeek 无隶属关系。
